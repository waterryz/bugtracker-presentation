# БагТрекер

Полный Flutter-проект для учёта дефектов с русским адаптивным интерфейсом, локальной SQLite и поддержкой Chrome. Анимированная презентация находится в папке `presentation/`.

## Запуск приложения в Chrome

Требуются установленный Chrome и Flutter с Dart 3.13.5 или новее.

```powershell
git clone https://github.com/waterryz/bugtracker-presentation.git
cd bugtracker-presentation
flutter --no-version-check pub get
.\run_chrome.bat
```

На Windows скрипт использует Flutter из `C:\flutter`, если он там установлен, иначе ищет `flutter` в PATH. Он работает относительно своей папки, поэтому проект можно скачать в любое место.

Прямая команда из корня проекта:

```powershell
flutter --no-version-check run -d chrome --web-hostname=127.0.0.1 --web-port=8766 --no-web-resources-cdn
```

На первом экране создайте локальный аккаунт или нажмите **«Посмотреть демо»**. Демо содержит три проекта и девять дефектов в отдельной учётной записи.

В VS Code или Android Studio открывайте корень репозитория, где находится `pubspec.yaml`.

## Возможности

- Регистрация, вход, профиль и восстановление сессии.
- Создание, редактирование и удаление личных проектов.
- Дефекты с описанием, шагами, ожидаемым и фактическим результатом, окружением, приоритетом и серьёзностью.
- Поиск, фильтры, сортировка, список и канбан с перетаскиванием карточек.
- Статусы: Новый, В работе, Исправлен, На проверке, Закрыт и Переоткрыт.
- Комментарии, журнал изменений, вложения и просмотр изображений.
- Обзор состояния проектов и распределение дефектов по статусам.
- Экспорт JSON с данными и вложениями, без паролей. Обратный импорт пока не реализован.

## Где хранятся данные

В Chrome работает SQLite WebAssembly с хранением в IndexedDB. Worker и WASM включены в `web/`; внешний сервер базы данных не требуется. Вложения сохраняются в базе браузера.

Локальная база привязана к адресу, порту и профилю браузера. Возвращайтесь на тот же адрес `http://127.0.0.1:8766`. Очистка данных сайта удаляет базу; `flutter clean` может удалить сохранённый отладочный профиль Flutter. Экспортируйте важные данные в JSON.

Для работы в обычном профиле Chrome запустите сервер из корня проекта, затем самостоятельно откройте указанный адрес:

```powershell
flutter --no-version-check run -d web-server --web-hostname=127.0.0.1 --web-port=8766 --no-web-resources-cdn
```

На Android и Windows используется локальный файл `tracker.sqlite` в каталоге поддержки приложения, подпапка `bugtracker`; вложения — в соседней папке `attachments`. Точный путь отображается в профиле.

Учётные записи изолированы. Исполнитель — сам пользователь или «не назначен»; роль описывает специализацию и не управляет правами. Облачной синхронизации, командных приглашений, REST API и push-уведомлений нет. База и вложения не зашифрованы; пароли хранятся через PBKDF2-HMAC-SHA256 с уникальной солью и 600 000 итераций.

## Структура проекта

| Путь | Содержимое |
| --- | --- |
| `lib/main.dart` | Запуск приложения |
| `lib/data/` | Модели, SQLite, авторизация и адаптеры платформ |
| `lib/ui/` | Экраны, формы, канбан и тема |
| `test/` | Тесты хранилища и интерфейса |
| `web/` | Chrome, SQLite WASM и worker |
| `android/`, `windows/` | Исходники и настройки нативных платформ |
| `pubspec.yaml`, `pubspec.lock` | Зависимости Flutter |
| `run_chrome.bat` | Запуск в Chrome на Windows |
| `presentation/index.html` | Автономная моушн-презентация |

## Проверки

Из корня проекта:

```powershell
flutter --no-version-check analyze
flutter --no-version-check test --no-pub
```

Тесты используют временные SQLite-базы и не меняют пользовательские данные. Проверяют регистрацию, вход, сохранение, миграцию базы, CRUD, комментарии, вложения, экспорт, каскадное удаление, изоляцию аккаунтов и адаптивный интерфейс. Это обычные Flutter-тесты для Dart VM; запуск с `--platform chrome` для этих тестовых файлов не предусмотрен.

## Другие платформы

Основной сценарий — Chrome. В репозитории также сохранены исходники Android и Windows.

```powershell
flutter --no-version-check devices
flutter --no-version-check run -d DEVICE_ID
flutter --no-version-check run -d windows
```

Для Windows нужны Visual Studio с компонентами Desktop development with C++ и поддержка символических ссылок. На исходном компьютере Visual Studio отсутствовала, поэтому EXE не собран.

Android APK можно собрать через `scripts/build-android.ps1`. Финальная проверка Android-сборки была прекращена по запросу пользователя; готовый проверенный APK здесь не поставляется. Текущая release-конфигурация использует отладочную подпись и не подготовлена для магазина.
